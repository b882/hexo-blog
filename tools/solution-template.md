# 算法题解正文模板

`tools/publish-algorithm.mjs` 只做确定性发布，不生成讲解内容。讲解由 Harness 会话中的 AI 依据
「题目原文 + 用户提交的 C++ 代码」撰写。本文件规定正文结构，保证多篇题解风格一致。

## 正文骨架

```markdown
## 题意

用自己的话重述题目：输入是什么、输出是什么、数据范围、多组数据与否。
题目来源写一行链接（可选）。这一段保持简短，Hexo 的首页摘要会截到 `<!-- more -->`。

<!-- more -->

## 核心思路

从题目性质出发，说明为什么这样建模、状态/贪心选择/图论模型是怎么想出来的。
点出关键观察，并说明它对解题的决定性作用。

## 算法设计

按执行顺序描述：初始化、转移方程、枚举顺序、边界处理、答案位置。
公式用行内代码或 `$...$`，不要写与代码不一致的伪代码。

## 正确性说明

给出必要的归纳、交换论证或反证；只写真正成立的结论。
无法严格证明的性质明确写「此处为直觉说明，未给出严格证明」。

## 复杂度分析

时间复杂度和空间复杂度都用大 O 表示，并说明每个量对应什么（n、m、值域、状态数）。

## 完整代码

{{CPP_CODE}}

## 易错点

只写真实存在的坑：溢出、边界、初始化、多组数据清空、下标从 0/1 开始等。
没有就省略本节。
```

## 写作规则

1. 以用户提交的 C++ 代码为准，讲解必须与代码的实际做法一致；不要按「标准解法」臆写。
2. 不编造题目条件、样例、数据范围、评测结果；题目信息不足时在正文里说明「题目未给出」。
3. 不修改用户代码，连缩进和空行都保留；代码由脚本嵌入 `{{CPP_CODE}}`。
4. 不写「经测试 AC」之类的结论；没有实际评测就明确说未经评测。
5. 中文讲解，术语保留英文原名（DP、并查集、树状数组等）。
6. 算法标签由 AI 推断，写进 `meta.json` 的 `tags`，例如 `["动态规划","区间DP","括号序列"]`。
7. 正文不写一级标题，不写 front-matter，章节统一用 `##`。
